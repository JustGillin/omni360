# Project Layout

The repository is a Visual Studio 2010 Xbox 360 solution, `Omni360.sln`. The main project is `XboxTLS2.vcxproj`, which builds `Omni360.xex`.

The project file keeps its original name even though the app no longer does — it is named after the TLS wrapper it was originally built around. Renaming it would mean reworking the solution's project GUID references for no functional gain, so it was left alone.

## Solution Projects

Only two projects remain:

`XboxTLS2.vcxproj` is the main executable. It holds the app entry point, the archive.org client, the drawn UI, STFS parsing, HTTPS download logic, the XboxTLS wrapper, the DNS helper, logging, and the embedded BearSSL sources.

`Common/AtgFramework2010.vcxproj` builds the ATG framework — Microsoft helper/sample code. The app uses it for the on-screen console, D3D device setup and font rendering. Its internals are out of scope here.

X-Store's other five projects (`user interface`, `7zip`, `xiso extract`, `updater`, `miniz`) were deleted along with the features that needed them. They are gone from disk and from the solution; if a document still references them, that document is stale.

## App-Owned Source Areas

`main.cpp` drives the whole user-facing flow: mounting drive aliases, console setup, the game-list session loop, settings parsing, and the DLC / title-update download paths.

`ArchiveOrgDLC.cpp` / `.h` is the archive.org client — IAS3 authentication, metadata lookup, fuzzy game-name matching (`ScoreDlcMatch`), RAR header-chain and ZIP central-directory walking, avatar-item filtering, already-installed detection, and the destination rules for both DLC and title updates.

`GameListUI.cpp` / `.h` is the drawn UI: the icon-grid game picker, the choice picker, the progress bar, and status/message screens. It renders with D3D quads and a gradient pixel shader rather than text on a blank framebuffer.

`StfsParser.cpp` / `.h` reads STFS package headers — title ID, display name and the embedded thumbnail used as cover art. Field offsets come from the Free60 wiki's STFS page (Metadata Version 1).

`Keyboard.cpp` / `.h` wraps the XDK on-screen keyboard, used for first-run key entry.

`downloadFile.cpp` / `.h` implements HTTPS downloads and HTTP response handling on top of XboxTLS. It streams to a file or fills a caller-provided memory buffer, and reports byte-level progress through a callback. Note that file-mode requests do **not** follow redirects — the caller re-resolves a 302 through buffer mode.

`XboxTLS.cpp` / `.h` wraps BearSSL into a small Xbox-friendly TLS 1.2 client API: context allocation, trust anchor insertion, socket setup, encrypted reads/writes, cleanup.

`dns.cpp` wraps `XNetDnsLookup()` with guarded failure handling and a small static fallback cache.

`parsing.cpp` / `.h` holds low-level helpers for URLs, HTTP headers, transfer-encoding detection and chunk sizes, plus `LogEscapePercent()` — the logging path formats twice, so a `%` in a URL has to be doubled or the string is mangled.

`OutputConsole.cpp` / `.h` and `Debug.cpp` / `.h` log to the ATG console, the debug channel and `game:\DebugInfo.txt`. `SetConsoleQuiet()` stops the console repainting over the drawn UI without silencing the log.

`driveMount.c` / `.h` (named `Corona4G.c` / `.h` in X-Store) comes from a Simple 360 NAND Flasher-style helper set. The app uses its `mount()` wrapper to create the `game:`, `Usb0:`, `Usb1:` and `Hdd:` aliases — nothing else in the project declares `mount()`, so it is load-bearing despite looking like vendor debris. The NAND read/write helpers in the same file are inherited and unused.

`TrustAnchors.h` holds the compiled-in TLS root certificates, added during handshake setup in `downloadFile.cpp`. The console has no OS certificate store, so every root is embedded. The header is generated by `tools/make_trust_anchors.py` from the certificate files in `tools/trust-anchors/`; that script documents where each came from and how it was checked.

`settings.h` holds the version string and `MAX_TEXT_LENGTH`.

## Embedded Libraries And Vendor Code

`SSL/` is BearSSL source, compiled directly into the main binary. These docs cover how `XboxTLS.cpp` uses BearSSL, not BearSSL internals.

`Common/` is ATG/XDK sample framework code, treated as a black box.

`cJSON.c` / `.h` is MIT-licensed third-party JSON parsing. It was originally pulled in for the updater's GitHub release JSON; the updater is gone, but `ArchiveOrgDLC.cpp` now uses cJSON to parse archive.org's item metadata, so it is still live.

## Build Artifacts

Generated output under `Release/`, `Debug/`, `Profile/`, `ipch/` and `Common/Release_LTCG/` is not part of the source architecture and should not be read as documentation.

## Runtime Files And Paths

`game:\ArchiveOrgKeys.txt` holds the archive.org IAS3 access key (line 1) and secret key (line 2), in plain text.

`game:\settings.txt` optionally sets `xbla-path:` (where content installs) and `games-path:` (where the library is scanned).

`game:\DebugInfo.txt` is the main log file.

Downloads are written straight to their final destination — `Content\0000000000000000\{TitleID}\{ContentType}\` for DLC and lowercase `tu...` updates, `{device}\Cache\` for uppercase `TU_...` updates. There is no temporary archive or extraction folder, because archive.org serves members already extracted.
